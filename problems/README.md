# Problem catalogue

Static, buildless catalogue at `/problems/`. It adds to the existing raindrops blog without replacing its homepage, authentication or Firebase data.

## Data

`data/catalogue.json` is a reviewed snapshot exported from the canonical IMO Shortlist, RMM and USA TST workbooks. It contains original classification summaries, the stable 88-label taxonomy, evidence types, caveats and source links. Verified problem statements are stored separately; solutions are linked rather than republished. Pending classifications are never fabricated as completed reviews.

The grid collection selector is populated from the current data, searchable by name or abbreviation, and horizontally scrollable (touch/trackpad or arrow buttons when it overflows). Arrow keys move between collection buttons; Enter selects the sole search match, and Escape clears the collection search. Grid links preserve the selected collection in `?view=grid&grid=…`.

Verified TST and RMM statements can appear before classification. `statement-catalogue.mjs` adds these only in the browser, with no tags and an explicit **Classification pending** label. They work in lookup, grid, notes and progress; method filters exclude them until actual tags arrive. Exact reviewed catalogue keys take precedence on later exports. The reviewed catalogue and its workbook snapshots remain unchanged by this display step. `statement-view.mjs` merges non-held supplements with active statements, preserving active objects. Held sources are not exposed automatically.

Both RMM main papers and shortlists are in scope; current coverage is explicit in the site. The USA TST (for the IMO only; not TSTST or the TST for EGMO) is a third contest with keys such as `usatst:2026:5`, added from 2026 backwards. Its workbook is `~/Downloads/USA-TST/USA TST Classification.xlsx` (same Problems A:U and Taxonomy layout as RMM; research and the guarded writer in `~/Downloads/USA-TST/research/`). Official solutions: the USA TST archive on GitHub (usa-tst-public, TST 2025 onward) and Evan Chen's solution files (web.evanchen.cc, to TST 2025); `--usatst` is optional in the export. `Live forum checked` and `Archived forum checked` describe the recorded check source, not a guarantee that all replies are complete correct proofs.

Refresh from the current canonical workbooks, without modifying them:

```sh
python3 scripts/export_catalogue.py --imo '/path/to/IMO Shortlist Classification.xlsx' --rmm '/path/to/RMM Classification.xlsx' --usatst '/path/to/USA TST Classification.xlsx' --output problems/data/catalogue.json
node --test tests/catalogue.test.mjs
python3 -m http.server 8765 --bind 127.0.0.1
```

Requires Python `openpyxl` for read-only export. The website itself needs no build step or backend. Readers can tick problems as done (saved in the browser); signing in by an emailed one-time link (Firebase passwordless auth, project in `../firebase-config.js`) syncs those marks to Firestore at `progress/{uid}` (see `../firestore.rules`). The page has three tabs: Problem lookup (the filtered list), Progress grid (every available ISL or RMM problem by year, green when done, with filter matches highlighted; clicking a square offers mark done / open / add to collection) and Collections (named lists with descriptions, stored with the done marks). Each problem's page also has private notes (autosaved; in the browser, or Firestore progress/{uid}/notes/{key} when signed in). Notes (per-problem and the notebook) render LaTeX, including text-mode lists (`enumerate` with optional labels such as `[(a)]` or `[label=(\roman*)]`, `itemize`, `description`, `\item[…]`) and `\textbf`, `\textit`, `\emph`, `\underline`, `\texttt` (`problems/notes-view.mjs`); math environments such as `align*` work as in MathJax. `[\hide="Label"] … [\hide]` hides the enclosed text in a box that opens on click (`problems/notes-view.mjs`; a bare `[\hide]` closes the box, boxes nest). On desktop the filters sidebar can be collapsed to a thin rail on any view (remembered in localStorage). While a problem is open, a Focus button fades out everything except the statement and notes (with the rendered LaTeX preview) and enlarges them in place; Esc or the button leaves it. The notebook (`problems/notebook.mjs`, pure helpers in `notebook-core.mjs`, styles under `.nbk` in `catalogue.css`) is a small black-and-white book (inverted in dark mode) that sits in a corner and can be dragged anywhere; clicking it swings the cover open into a two-page spread. The left page lists the tabs (add, double-click or ⋯ to rename, drag or ⋯ to reorder, delete); the right page shows the open tab with Edit (plain text, autosaved) and View (LaTeX, `[\hide]` boxes, and problem names such as `2019 C6` or `RMM 2017/6` linked to their entries; View has its own text size, A/A in the header or Ctrl/⌘ +, −, 0, and equations scale with it) and a ribbon that closes the book. Both pages' contents fade in together once the cover has landed. The handle in the middle slides left or right to give one page more room (double-click evens them out). Drag the open book from its frame, anywhere on the left page, the right page's header, or empty space in View mode; resize it from any side or corner (the west edge grows the left page, the east edge the right page). Opening and closing follow the book's current shape: the cover swings about the middle and is sized at each angle so it never reaches past the book's edges; narrow screens get a single page with a Tabs button. Tabs are kept in the browser when signed out and at Firestore `progress/{uid}/notebook/{tabId}` when signed in (local tabs are added to the account on first sign-in). Position, size, mode and the open tab are remembered per browser. The design follows the user's `book-widget.js` reference; the favicon (`/favicon.svg`, black, white in dark mode; `/favicon.ico` fallback) is the same book. Search state and entry permalinks live in URL query parameters. Filters include collection, descriptive subject, years, source-review type and all60 primary/additional method tags; multiple tags support AND/OR and primary-first ranking.

Forum-check guidance for workbook reviewers (2026-11-16): light forum passes so far read only the first ~10 posts of each AoPS thread. Short, clean solutions tend to appear near the END of long threads (posted later, after official solutions circulate), so every live or archived forum check should also read the last ~10 posts, and record the post ranges actually read (e.g. `#2–#9, #41–#52 of 52`) in the reviewed-solution references. Existing rows whose references cite only low post numbers in long threads are candidates for a tail pass. Tail-pass results live in `data/tail-pass.json` and are re-applied by `scripts/tail_pass.py` (also called from the export), adding tags only and never changing a primary.

Keep workbook review/source caveats intact during refresh. Snapshot provenance includes input hashes without local machine paths. Do not publish arbitrary research caches, credentials, Firebase data, or project administration notes.

## RMM statement sources (2026-11-17)

All 98 main-paper statements across the 17 published editions have been collected; all 94 currently classified RMM entries have active statements. The four remaining main-paper sources await catalogue entries, rather than statement research.

`data/statement-supplements.json` also holds all 81 numbered statements in the eight populated AoPS shortlist branches: 2016 (9), 2017 (8), 2018 (9), 2019 (11), 2020 (11), 2021 (12), 2023 (9), and 2024 (12). The two versions of 2019 SL G4 share their original label; the three withdrawn 2019 Day 2 statements have separate `original P4`–`original P6` keys and must not replace the contest paper. AoPS's 2019 shortlist numbering differs from the compiled booklet because selected contest problems were omitted; preserve the AoPS IDs.

The 2025 shortlist branch still contains only subject headings; no 2026 shortlist branch or pre-2016 shortlist branch was listed in the collection when checked. These are source-publication limits, not empty completed inventories. In 2020 SL G3, the source omits the definition of I; a labelled statement note identifies I as the incircle centre from the supplied solution. The original two displayed conditions and caveat for 2021 SL A3 are retained.

The exporter attaches supplements to exact existing reviewed catalogue keys when invoked. Separately, the browser can show verified statement-only TST/RMM entries with classification pending; this does not complete a proof review or continuously refresh the published source files.

## USA TST statements (2026-11-17)

All 172 original problem slots in the listed 2000–2026 AoPS USA TST editions have statement sources, including geometry and problems not yet tagged. There was no 2022 winter TST. The current source inventory is 6 problems per edition except 2021 (3), 2012–2013 (8 each), and 2001/2008/2009/2010/2011 (9 each). This is the IMO TST, not TSTST or EGMO TST.

Sources are the public official USA TST archive (2026), Evan Chen's supplied papers/TeX (2014–2025), and the complete rendered AoPS year collections with their provided printable PDFs (2000–2013). Original labels, topic links, collection context, authors and source hashes are retained. Opening statements rendered in collections are not claimed as new solution/forum-proof reviews.

In 2012 and 2013, numbering restarts at 1 in the December and January papers. Keys use `usatst:2012:Dec 1` and `usatst:2012:Jan 1` (and likewise 2013); preserve these distinct original sessions. Do not flatten them into guessed 1–8 labels on a later classification export. Two source notes remain visible: 2003/4 omits the domain restriction needed for f(m−n), and 2005/3 switches g/f and uses “unitary” for monic. The source wording is retained with explicit notes.

## Hosting

The folder works with an existing GitHub Pages deployment from the repository root. Ensure the `.mjs` files and `data/catalogue.json` are served. The repository visibility/Pages plan is configured separately by its owner; this change does not change access settings or Firebase rules.
